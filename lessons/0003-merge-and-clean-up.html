Merge and clean up

Bringing a branch home, then throwing away the pointer.

You will merge a branch into main, recognise a fast-forward versus a merge commit, delete branches safely, and resolve a real merge conflict.

Two kinds of merge

A merge brings another branch's commits into the branch you are on. You always merge into HEAD, so first switch to the branch that should receive the work (usually main), then run git merge <branch>.2

  • Fast-forward. If main hasn't moved since the branch started, there's nothing to combine. Git just moves the pointer, "because there is no divergent work to merge together — this is called a 'fast-forward.'"1
  • Merge commit. If both branches gained commits, Git does a three-way merge using the two branch tips and their common ancestor. The result "is referred to as a merge commit, and is special in that it has more than one parent."1

git merge --no-ff <branch> means "Create a merge commit in all cases," even when a fast-forward was possible.2 GitHub's default Merge pull request button does exactly this.5 You'll meet it in lesson 4.

Deleting a branch is deleting a pointer

Once a branch is merged, its commits live on in main. The branch is just a leftover label, so delete it with git branch -d <branch>.1 The lowercase -d is the safe version. The branch "must be fully merged," and if it isn't, Git refuses:3

$ git branch -d try-polars
error: the branch 'try-polars' is not fully merged
hint: If you are sure you want to delete it, run 'git branch -D try-polars'

Uppercase -D ("--delete --force") deletes it anyway.3 That's the right move for a failed experiment, such as an agent attempt you've decided to abandon, but it throws those commits away. Read the error before reaching for -D.

Your first merge conflict

Git can't decide for you when "you changed the same part of the same file differently in the two branches."1 That's a merge conflict. It isn't an error, just a question Git needs you to answer. GitHub has the same rule: the Merge pull request button stays disabled until conflicts are resolved.4 Make one on purpose so it's familiar before an agent hands you one.

  1. $ git switch -c readme-title
#   ...edit line 1 of README.md...
$ git commit -am "Retitle README"
$ git switch main
  2. $ git switch -c readme-title-2
#   ...edit line 1 of README.md...
$ git commit -am "Rename project in README"
$ git switch main
  3. $ git merge readme-title
Fast-forward
$ git merge readme-title-2
Auto-merging README.md
CONFLICT (content): Merge conflict in README.md
Automatic merge failed; fix conflicts and then commit the result.
  5. <<<<<<< HEAD
# Palmer Penguins Analysis
=======
# Penguin Data Lab
>>>>>>> readme-title-2

    Above ======= is the version from HEAD, the branch you're on. Below it is the branch you're merging in.1 Edit the block until it says what you actually want, for example # Palmer Penguins Data Lab, and delete all three marker lines.

  6. $ git add README.md
$ git commit -m "Merge readme-title-2, combine titles"
$ git branch -d readme-title readme-title-2
Search the file for leftover <<<<<<< before you git add. Git will happily commit marker lines, and a .py file with markers in it won't even import.

Check yourself

main hasn't moved since you created add-cleaning. What does git merge add-cleaning do?

  • slide main's pointer forward
  • create a two-parent commit
  • always raise a conflict
  • delete the add-cleaning branch

No divergent work means a fast-forward. Git just moves main to the branch tip, and no new commit is made.

git branch -d add-plot fails with "not fully merged." What is Git warning you about?

  • Deleting it would lose commits
  • The branch has a conflict
  • GitHub must approve the delete
  • You must push it first

add-plot has commits that aren't in your current branch. Merge first, or use -D if you really mean to throw them away.

In a conflict block, what is the text above the ======= line?

  • your current branch's version
  • the incoming branch's version
  • the original common ancestor
  • Git's suggested final resolution

The top half is HEAD, the branch you ran git merge from. The bottom half is the branch being merged in.
